# Logic Fit UI/UX Screen Map

This map is derived from the source inventory generated by
`scripts/discover-screens.js`. It describes the intended information
architecture without changing routing or business behavior.

## Surface map

| Surface | Route | Primary user | Purpose | Primary action | Responsive composition |
|---|---|---|---|---|---|
| Gym Application / public entry | `/` and `/#dashboard` | Owner / Assistant | Enter the tenant workspace and operate the gym | Log in / open the selected workspace | Desktop workspace with page tabs; compact priority navigation on mobile |
| Platform Admin | `/platform-admin` | PlatformAdmin | Operate the Logic Fit SaaS control plane | Review the item needing attention | RTL control-center sidebar on desktop; off-canvas navigation on small screens |
| Member Portal | `/member-portal` | Member | Read membership data and use member services | Verify membership code | Mobile-first entry card, then service hub and focused subviews |
| Register Gym | `/register-gym` | Prospective gym owner | Submit a Logic Fit subscription request | Send registration request | Context/progress panel on desktop; step/progress flow on mobile |
| Forbidden state | `/platform-admin-forbidden` | Non-platform user | Explain access boundary | Return to a safe entry point | Single centered state with no admin navigation |

## Nested workflows and overlays

The static inventory found 19 nested/step hooks, 8 Store subviews, 5 Member
Portal tools, 20 dialog roots and 165 form/filter/action hooks. Every overlay follows the existing dialog contract:
short actions use a modal, details can use a drawer-like panel, and mobile
content remains inside a bounded viewport with internal scrolling. The shared
feedback layer owns loading announcements; individual feature code owns the
server result and business-specific success/error message.

## State contract

Each data-driven surface is reviewed against:

`initial → loading → loaded | empty | error → retry/success`

Permission-denied, disabled, submitting and long-content states are included
where the underlying feature exposes them. Structural browser QA proves the
DOM, overflow and theme contract. The latest complete pass produced 811
evidence records with zero page errors, unexpected console errors or
unexpected failed responses; protected-API 401 responses in logged-out forced
states are recorded separately. Authenticated data, role matrices and
production-device behavior require the authorized E2E environment and are
not inferred from a static screenshot.
